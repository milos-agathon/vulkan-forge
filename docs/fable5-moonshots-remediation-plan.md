# Fable 5 Moonshots — Remaining Implementation and Remediation Plan

**Baseline:** live `main` at `ae0e28aded5beffc2ff98a6b2e740170ecec5a96`, verified 2026-08-05, plus the lightweight CENSOR policy closure shipped with this plan. This plan applies the literal local prompt contracts to that code, its tests, workflows, and merge history. Most original prompt files were previously intentionally untracked, so a merged implementation alone was not evidence that its prompt document was present on `main`.

**Scope and ordering:** the table contains every unfinished numbered prompt plus the separate CENSOR remediation follow-up, retained as the now-closed policy predecessor. Already closed items `01`, `02`, `04b`, `08`, `10`, `13`, `14`, `17`, `30`, `32`, and `34` are omitted except where they are predecessors. The order is the default delivery sequence; proof-only work may proceed in parallel when it does not violate the listed hard predecessors. `CLOSED` means no implementation remediation remains for that row; `PARTIAL_MERGED` means material implementation exists but literal requirements remain open; `CODE_COMPLETE_ACCEPTANCE_NOT_PROVEN` means the implementation and gate machinery are merged but the required exact-head evidence is missing; `ABSENT` means the prompt-specific deliverable is not on `main`; `UNMERGED` means relevant work exists outside `main` and must be reconciled before it counts.

**Validation policy:** no moonshot may add a heavyweight required check to routine GitHub pull-request CI. Branch protection should contain only fast build, lint, unit, contract, and small deterministic smoke checks, with no dependency on a scarce physical runner. Multi-device comparisons, full-resolution or full-corpus benchmarks, exhaustive fuzzing, long flythroughs, and soak tests run only for explicit moonshot acceptance or a release candidate, preferably on dedicated lab infrastructure outside ordinary GitHub Actions. Routine GitHub checks may validate an untrusted result schema or a previously signed manifest, but production signing and unavailable lab capacity must never block unrelated feature work. The final column is therefore a moonshot completion gate, not a per-PR gate.
